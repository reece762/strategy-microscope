五票制引擎：一行寫錯，讓它十年只進場 15 次

他的「五票制」把 EMA 斜率、價格與 20 日均線、高低點結構、趨勢棒佔比、K 線重疊率各投一票，總分 ≥3 才看多。但「趨勢棒佔比」那一票的程式寫成兩個分支都回傳 −1——上漲棒越多，它越投空。後果是 SPY 十年只出現 0.9% 的看多日、實際進場 15 次、曝險 0.9%，年化 -0.32%。

先說這張卡的來源。 這位作者的 B 站空間與影片頁全部被風控擋住（HTTP 412、錯誤碼 −352），我沒有取得任何一集的逐字稿。所以我沒有聽過他任何一支影片，這張卡驗的是他 GitHub 上開源的程式碼（will2085991040-ui/density-sr），不是他影片裡的口頭說法。程式碼是他自己公開的，檔案 aiquant/engine/signals.py 第 35 行，任何人可以自行核對。

那一行是這樣寫的：v = -1 if upr >= 0.6 else (-1 if upr <= 0.4 else 0)。upr 是最近 10 根 K 線裡「收盤高於開盤」的比例。如果 upr 大於等於 0.6（上漲棒超過六成），回傳 −1；如果 upr 小於等於 0.4（上漲棒不到四成），也回傳 −1。兩個分支都是 −1，這一票永遠不可能投 +1。

從意圖看應該是什麼？ 上漲棒超過六成是多頭訊號，所以第一個分支應該回傳 +1。合理推測是複製貼上時漏改：1 if upr >= 0.6 else (-1 if upr <= 0.4 else 0)。但我不想替他猜意圖——我只確定現在這個寫法，趨勢越強、投票越空。

為什麼後果這麼大？ 五票裡有一票永遠 ≤ 0，總分上限就被壓到 +4，而他的看多門檻是「總分 ≥ 3」。等於剩下四票要幾乎全對才開得了口。實測 SPY 的總分範圍是 [-5, 4]、QQQ 是 [-5, 4]、BTC 是 [-5, 3]——上限 4、下限 −5，整個分布往空方偏。

結果是一台幾乎不開口的機器：SPY 十年 15 次進場、曝險 0.9%、年化 -0.32%；QQQ 18 次、0.8%、-1.12%；BTC 17 次、0.8%、-2.55%。看空的日子是看多的 25 倍以上（SPY 22.4% 對 0.9%）。

我把那一票改成 +1 之後重跑：SPY 看多日回到 19.1%、進場 178 次、曝險 19.1%、年化 +1.33%；QQQ +3.64%；BTC +13.67%。修好之後仍然是輸給「同曝險、不擇時」的基準，但差距已經在誤差內（SPY 對基準的 t 值 -0.89、QQQ -0.17）。這很重要：修好 bug 不代表策略會賺，只代表它從「幾乎什麼都不做」回到「正常地參與市場」。

還有一個更危險的東西，它不會報錯。 引擎的支撐／阻力區是動態載入的：try: zones = _sr_zones(dfi) 然後 except Exception: zones = []，而後面發訊號的條件是 if long and support——沒有支撐區就不發訊號。所以只要那個載入失敗，整台機器就靜靜地什麼都不做，不報錯、不警告、介面看起來一切正常。對照之下，那個 −1 的 bug 至少行為可預期（偏空），靜默失效才是最難發現的一種錯。

我沒有修他的程式，也沒有提交任何東西。 這張卡只是把「一個字元打錯，讓系統十年只進場 15 次」這件事量化出來。如果你要拿他的工具做任何事，第一步應該是先確認這一票是不是你要的方向。

判定：程式有實質錯誤：那一票永遠不可能投多，導致系統性偏空。修好之後不再偏空，但仍然贏不過同曝險基準——錯的是實作，不只是一個參數。
